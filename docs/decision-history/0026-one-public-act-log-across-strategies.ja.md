# ADR-0026: 著者の戦略が共有する公開の行為ログ 1 本

> **要約.** 著者の戦略 —— この framework と、著者の personal-branding 戦略 ——
> の行為は、公開の行為ログ 1 本（implementation log）に、行 ID と各行為を実施した
> 戦略を添えて記録する。人向けの経路は機械にも届き、その逆も成り立つので、行為の
> 意図でその効果を分けることはできない。公開の場で行った行為は場所と URL を名指し、
> 非公開の経路（フォーム・申請・メール）で行った行為は行為があったことだけを記録する。
> ログには理由を書かない。相手の反応・連絡先・個人的な事情は非公開のノートに残す。
> 作業の queue は計画とログの ID を持ち、行為の第二の記録を持たない。過去の行は残し、
> 名前は日付つきの補記として足す。すべての行為を公開のログに残すことは、著者が
> 公開できる行為を選び続けることにもつながる。

## Status

accepted

## Date

2026-10-12

## Context

Plan: [docs/plans/shared-act-log-convention.html](../plans/shared-act-log-convention.html)（2026-10-12 承認）

**分け方は意図に沿い、効果は沿わない.** 2026-10-12 の早い時刻に、
[ADR-0025](0025-planning-and-task-state-in-a-public-rfc-store.ja.md) は計画と
タスクの状態を公開 `rfcs/` store に移し、implementation log を intervention
timeline として残した。[ADR-0024](0024-success-as-arrival-at-the-dated-record.ja.md)
の Decision 5 では、行為を動機づけた狙いを持つ戦略がその効果を記録するので、
personal-branding 戦略は非公開の repository に自らの行為ログを持ち、この program は
それを写さずに読むことになっていた（commit `bc76573`）。そのあと著者は、意図では
効果を分けられないことを指摘した: 人の読み手に向けた掲載も crawl され、機械向けの
面も人を record へ連れてくる。ADR-0024 は成功を dated record への到達で判定し、
その判定は、他に日付つきの記録を持たない行為が、誰が実施したかによらず 1 本の
時系列に並んでいるほど読みやすい。

**伏せていたものと、その理由.** timeline は、
[ADR-0014](0014-implementation-tracking-two-tier-ledger.ja.md) の Decision により、
運用詳細を [ADR-0012](0012-link-index-channel-selection.ja.md) の水準に抽象化して
いた。ADR-0014 が挙げた理由はプライバシーで、運用詳細を公開記録に入れると、抽象化
すべき情報が露出するというものだった。この理由の下には 2 種類のものがあった。
相手の反応・連絡先・個人的な制約は行為の周辺の文脈で、行為ではなく、非公開に残し、
どのログにも入れる必要がない。公開の場で行った行為の host 名と URL は別で、pull
request・投稿・プロフィールの編集・deposit は、行った場所で既に公開されているので、
名指しても新たに明かすものはない。非公開の経路で行った行為は外から見えないので、
ログには行為があったことだけを記録する。

**集約.** [ADR-0021](0021-self-sovereign-entity-grounding.ja.md) は、働きかけを、
個々の行為が host の規約を形式的に満たすかだけでなく、累積の足跡で判断する。公開の
ログは多くの場所の行為を 1 ページに集め、その足跡を一度に見せる。そのようなログの
公開を制裁に結びつける証拠はなく、リスクが上がるというのは仮説である。著者は、
足跡は行為そのもの —— どの host に、どの頻度で、作者であることを開示して —— が
決め、記録を伏せてもそれは変わらないと判断した。著者は 2026-10-12、この設計を
選んだ plan の議論の中で、両戦略の行を公開することを受け入れた。

**レビュー.** plan の cross-vendor レビュー（gpt-6-astra）は、作業 queue が第二の
記録として残ること、無人の書き手が行を失いうること、過去の行の書き換えが
ADR-0021 の歴史保存と衝突すること、この判断が複数の repository・常駐の rule・
自動化にまたがることを指摘した。Decision 4・6・8 と、この記録の形はその指摘に
よる。

## Decision

1. **公開の行為ログ 1 本.** 著者の戦略の行為は
   `docs/empirical/implementation-log.md` に記録する。2026-10-12 からは時系列の
   節が、1 行為 1 行で、ID・日付・行為を実施した戦略（By）・行為・場所・record への
   経路を持つ。By は誰が行為を実施したかを示すだけで、効果を帰属させない。
2. **公開の場は名指し、非公開の経路は名指さない.** 公開の場で行った行為は場所と
   URL を名指す。非公開の経路（フォーム・申請・メール）で行った行為は、場所も URL も
   書かず、行為があったことだけを記録する。公開の場の行為については、ADR-0014 が
   timeline に適用した抽象化をこれで置き換える。
3. **ログに理由を書かない.** 理由は行為を実施した戦略の計画の置き場 —— この
   framework なら `rfcs/` —— へ行き、そこには機微でない理由を書いてよい。相手の
   反応・連絡先・個人的な事情は非公開のノートに残す。
4. **1 つの事実に 1 つの記録.** 作業の queue は、計画・操舵・非公開の文脈と、
   完了した行為のログ ID を持つ。行為の URL や日付を第二の記録として持たない。
5. **範囲はログの冒頭に書く.** ログは第三者の面での行為と dated record への介入を
   扱う。repository 内の変更（git 履歴と CHANGELOG が持つ）と記事の公開（公開先の
   platform が持つ）は扱わない。到達をまとめる読み手は、ログをそれらの記録と
   合わせて読む。
6. **過去の行は残す.** 既存の行には、名前を日付つきの補記として足す。失効や
   取り下げを記録した行は残す。古い行の戦略や経路が分からないときは、補記にそう
   書く。計画と見送りを扱っていたログの節は `rfcs/` へ移し（ADR-0025 Decision 2）、
   ログはそれを持つエントリを指す。以前の文面はファイルの履歴に残る。
7. **3 つの層、それぞれに正本 1 つ.** 常駐の harness rule `public-records.md` が
   公開記録の共通の境界を持つ。`docs/maintenance.md` の節「実施を記録するとき」が
   このログの範囲と列を持つ。scheduled task と skill が手順を持つ。
8. **無人の書き手は行を先に書く.** scheduled task は専用の branch に行を足し、
   その行の ID で queue の項目を閉じ、行の無い行為と、閉じた項目の無い行を報告する。
   session は diff を読み、public-detail の検査を通してから branch を取り込む。
9. **足跡は意図して保つ.** 行は中立の言葉で書き、By はログの冒頭で 1 度だけ定義した
   略号にする。掲載の task は累積の足跡の確認と停止条件を保ち、各提出で作者で
   あることを開示する。

## Alternatives Considered

**戦略ごとに 1 本のログ.** 却下: 両戦略に仕える行為は 2 度記録されるか、意図に
よって 1 つの持ち主に割り当てられることになる。ログを読む目的である効果は意図に
従わない。

**非公開のログと公開の投影.** 却下: ADR-0025 が退役させた二層 ledger を戻し、
同じ事実を 2 か所に置く。

**personal-branding の行を公開のログに載せない.** 著者が却下: 時系列が再び分かれ、
足跡は行為に依存し、伏せた記録はそれを変えない。

**新しい規約を新しい節からだけ適用する.** 却下: 過去の行は名指されないまま残り、
到達を判断する読み手は、初期の行為がどこで行われたかを個別に調べる必要が残る。
日付つきの補記は、行が当時述べたことを変えずに名前を足す。

**無人の task が検査を通して公開まで行う.** 却下: host を名指す行は push されると
release の snapshot・archive・mirror に広がるので、公開の前に人が diff を読む。

**ADR-0024 と ADR-0025 への日付つき注記だけ.** 却下: この変更は複数の
repository・常駐の rule・無人の task にまたがり、その読み手には理由の記録が
1 つ要る。

## Consequences

**Positive.**

- 他に日付つきの記録を持たない行為を、誰が実施したかによらず 1 本の時系列から読める。
- 各行為の記録は 1 つで、queue とログのまれなずれは照合が見つける。
- 著者は、公開で一覧されることを前提に行為を選ぶ。

**Negative.**

- 著者の働きかけの広がりが 1 ページで見える。
- push した行は実質的に取り消せない: Zenodo の release snapshot、Software Heritage の
  archive、dataset の mirror に広がる。
- 名指した URL は切れる。切れたリンクは日付つきの行に残る。
- empirical layer の methods companion に、この framework の戦術でない行為が入る。
  ログを戦術で切る読み手（`docs/empirical/tactic-lifecycle.md` など）は By で絞る。
- 無人で書かれた行は session が取り込むまで待ち、personal-branding 戦略は自らの
  文書と queue の形を変える。
- 過去の行は 2 つの書き方で読まれる: 元の抽象化と、日付つきの補記。

**Revisit when.** 著者が行為の前にそれをログに書くことをためらった、platform が
著者のアカウントについての判断でこのログを引いた、Decision 2 のもとで記録できない
行為が出た、3 つめの戦略がここに行為を記録し始めた。

## Lineage

この問いは 2026-10-12、ADR-0025 のあとに生じた。personal-branding の経路の非公開の
写しを外したとき（commit `bc76573`）、著者が implementation log はその戦略と共有されて
いるかを尋ねた。著者は意図と効果は分けられないと述べ、正本と公開用の分割を退け、
公開の場で行った行為は既に公開されているので名指してよいと判断した。plan は
gpt-6-astra のレビュー（9 件）を受けて改訂された。著者は両戦略の行の公開を受け入れ、
公開のログは行為を公開できるものに保つと述べ、この記録はそれを理由の 1 つとして採る。
その後の ADR レビューが、抽象化の出所と ADR-0024 Decision 5 との関係の記述を正した。
