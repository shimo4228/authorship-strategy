著者の行為は、公開の 1 本のログに行 ID と実施元つきで並ぶ。

queue と task の重複防止がこの ID を指す。 効果の帰属には使わない。到達の判定は ADR-0024 が行う。 行為があった事実だけ。場所も URL も書かない。

ログが網羅する範囲と網羅しない範囲は、ログの冒頭に書かれる。

既存の行は残り、名指しは日付つきの補記として足される。

補記で名指す。元の文と撤回・失効の記録は消さない（ADR-0021 の歴史保存）。

既存の 45 行をどう扱うか。

 移す節 「Not yet done」と「Explicitly out of scope」は計画と見送りなので、該当する rfc へのリンクに置き換える（例: RFC-0004、RFC-0025）。

同じ実施事実は、ログの 1 か所にだけ書かれる。

二重でないもの rfc の状態や .notes/ の詳細は、同じ実施事実を持たないので二層ではない。問題は同じ事実を 2 か所で別々に更新することだけ。

無人の task は、ログを先に書き、その ID で queue を閉じる。

task は専用の worktree で書き、重複と欠落を照合で見つける。

task の行を誰が公開するか。

最初の公開の前に、著者が集約した一覧を見て受け入れる。

PB の行を公開のログに載せるか。

規約は 3 層に分かれ、各層の正本は 1 つになる。

ほかの 2 層 AS と PB の範囲・列・保存先は AS の docs/maintenance.md（行為ログの節）。実行手順は listing-pr-daily と skill rfc-writer。rule はこの 2 つを名指さない。 権限 harness の rule と skill の編集は、auto mode の分類器が自己改変として止める場合がある。止まったら、その編集だけを著者に渡す。

検査 script は repo の外から呼べ、検査できないときは失敗する。

済み .notes/ が無い repo で LLM の出力が消えて OK になる不具合は、この plan の前に直した（b891298）。

判断は ADR-0026 に記録され、旧 ADR は注記でそこを指す。

文書はこのセッション、script はレビューつきで別に、PB は PB の session が書く。

実行者の決定: 誰が書くか。

共通: 公開記録の 1 行を 5 つの問いで決める。

変えないもの。

  • implementation-log の位置と名前、ADR-0023 の empirical な役割（介入と行為の時系列）。
  • 効果を主張しない規約。到達の判定（ADR-0024 Decision 4）は log を読む側が行う。
  • rfcs/ の store の形（ADR-0025）と、.notes/ を機微の置き場にすること。
  • zenn-content の schedule.json と metrics。生産と計測の記録で、行為ログではない。
  • 非公開 repo の整理（済み: 8 本を _archive へ移した）。
  • v1.2.0 の SWHID の記録。Software Heritage の失敗の扱いは別に決める。
